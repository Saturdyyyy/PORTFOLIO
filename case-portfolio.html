CASE STUDY 03 · FRONT-END + API

SATURDYYYY
PORTFOLIO

A hand-coded portfolio with a live Spotify integration, built without frameworks to learn what the tools normally hide.

RoleDesign and development
ScopeDesign, front end, API proxy, deployment
StackHTML, CSS, JavaScript, Canvas API, Node.js, Express, OAuth 2.0
HostingVercel (front end), Render (API proxy)

Overview

The goal was a portfolio that feels like a person, not a template. It uses a music-album structure, a dot-grid canvas background, a custom cursor and a live Spotify widget showing what is playing right now.

Technical highlights

  • Spotify integration: OAuth 2.0 refresh-token flow through a small Node/Express proxy. The browser never sees the client secret.
  • Endpoints: now-playing, recent tracks, play, pause, next and previous.
  • Canvas API: the interactive dot-grid background and a small catch-the-notes game.
  • Deployment: Vercel for the front end and Render for the proxy, both auto-deploying from GitHub.

Problems solved

  • Always-on backend: the local server had to run in a terminal, so it moved to Render, with the secret and refresh token stored as environment variables.
  • Redirect and origin errors: OAuth redirect URIs, CORS and file:// origins each broke the widget in a different way and each was traced and fixed.
  • Leaked secret: a secret pasted in the wrong place was rotated and moved to environment variables. A lesson in treating secrets as secrets from day one.

Redesign for hiring

This version reorders the site for a recruiter: what I do, proof of it, then the personality. The music theme stays as a signature rather than the navigation.
