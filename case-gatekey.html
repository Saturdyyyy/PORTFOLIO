CASE STUDY 01 · UI DESIGN + FRONT-END

GATEKEY

Interface design and front-end build for GateKey: the marketing website plus the Guard, User and Superadmin mobile apps.

RoleUI designer and front-end developer
ScopeWebsite + 3 mobile app interfaces
StackHTML, CSS, JavaScript, GSAP, Lenis, React Native (Expo)
Livegatekey.co.in ↗

Overview

GateKey is an access-management product with three kinds of people using it: guards at the gate, residents or users, and administrators. Each group needs a very different screen, so the work was one product with a website and three separate app interfaces that still feel like one brand.

My role

  • Designed and built the marketing website front end.
  • Designed and developed the interface for the Guard, User and Superadmin mobile apps.

The design problem

  • Guard app: used standing up, often in a hurry. Large tap targets, few steps, clear status colours.
  • User app: used occasionally. It has to be obvious without explanation.
  • Superadmin app: used for oversight. It needs dense information that is still scannable.

Approach

  • Defined one shared set of colours, type and components first, so the three apps stay consistent.
  • Built each role's screens around its single most frequent task rather than a generic dashboard.
  • For the website, used GSAP for scroll-linked animation and Lenis for smooth scrolling, keeping the layout responsive down to phone width.

Result

A live website and three app interfaces under one visual system. The website is public at gatekey.co.in.

What I learned

  • Designing for role-specific users changes the layout decisions more than any visual style choice does.
  • A shared component set saves more time than any single screen polish.
